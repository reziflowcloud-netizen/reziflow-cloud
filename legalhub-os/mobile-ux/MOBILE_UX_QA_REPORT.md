# Mobile UX QA Report

Date: 2026-09-16

## Coverage

- Widths: 360 sanity; primary 390, 414, 430 px.
- Screens: Dashboard, Leads, Cases, Clients, Lead Detail, Case Detail, Client Detail, Tasks, Stages, Calendar, More bottom sheet.
- Desktop regression: 769, 1024, 1440 px.
- Themes: Light, Dark, Slate.
- Languages: RU, UA, PL.
- Permissions: full-access admin, restricted own-records employee, and conference demo technical restrictions.

## Result

All 11 approved mobile screens pass responsive, navigation, theme, localization, safe-area, overflow, configured-color, date/time, and desktop-boundary checks. Mobile roots remain hidden from 769 px upward. No API, Prisma, database, auth, financial, document-security, or Meta behavior was changed.

## Issues found and fixed

1. More sheet exposed Settings navigation to non-admin employees. It now follows the existing admin/owner and conference-demo rules.
2. Mobile Tasks exposed task-priority configuration to employees/demo sessions. The existing configuration UI is now shown only to organization admins/owners.
3. Mobile Stages exposed status configuration to employees/demo sessions. The existing link is now shown only to organization admins/owners.
4. Leads, Cases, and Calendar used chess-like glyphs for person/case concepts. They now reuse a consistent compact person/document SVG language.
5. Two legacy autogenerated passport reminders stored date-only semantics as technical same-day `00:00`. Autogenerated passport tasks now render localized all-day text; genuine user-created midnight reminders still render `00:00`.

Issues found: 5. Issues fixed: 5. Remaining blockers: none.

## Verification

- No page-level horizontal overflow at 360/390/414/430 px.
- Lead/Case/Client nested navigation, Task relation navigation, and browser back pass.
- Lead/Case/Client save controls remain visible above bottom navigation; Task and Calendar edit/save flows are reachable.
- Dynamic Lead Status, Case Status, Service, Task Priority, and Stage colors use organization configuration with neutral fallback.
- Restricted runtime fixture verifies assigned Leads and hides responsible/configuration controls. The available restricted fixture has no assigned Case/Client/Task records; those empty scopes and presentation guards were verified without creating data.
- Security hardening suite: 15/15 pass.
- Lead visibility regression: 11/11 pass.
- TypeScript, Prisma validation, `git diff --check`, and safe `npx next build`: pass.

## Known limitations

- Existing desktop data tables/matrices may retain their intentional horizontal scrolling at narrower desktop widths; this predates and is outside the mobile presentation layer.
- A cold local Next.js development compile can briefly show loading state; production build completes successfully.
