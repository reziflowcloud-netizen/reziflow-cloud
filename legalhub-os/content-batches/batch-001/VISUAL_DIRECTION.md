# Visual Direction - Instagram Launch

Status: practical visual system for LegalHub CRM Instagram launch content.

Goal: make the account feel operational, B2B, specific to migration/legalization agencies, and visually clear without becoming dull or generic.

Needs clarification:

- Final brand palette and typography.
- Approved logo usage.
- Approved CRM screenshots and demo data.
- Approved UI mockups for public use.

## Visual Positioning

The Instagram should look like a modern operations desk for legalization agencies, not like a generic SaaS template.

The content should communicate:

- order after chaos;
- practical workflow control;
- document and deadline visibility;
- owner-level clarity;
- specialized CRM for legalization agencies in Poland.

Avoid:

- generic motivational business visuals;
- legal-advice imagery aimed at end clients;
- heavy stock photos of smiling office teams;
- fake "AI automation" aesthetics;
- exaggerated alarmist visuals;
- cluttered screenshots that no one can read on mobile.

## Colors

Use a restrained B2B palette with enough contrast and energy for Instagram.

Recommended working palette:

- Deep navy: `#14213D` for headings, cover backgrounds, serious owner-focused posts.
- Signal teal: `#1B998B` for CRM highlights, active states, workflow lines, positive structure.
- Warm amber: `#F4A261` for warnings, deadlines, attention labels, "chaos" moments.
- Clean off-white: `#F8FAFC` for backgrounds and slide surfaces.
- Soft gray: `#E5E7EB` for grids, dividers, spreadsheet references, UI framing.
- Graphite: `#1F2937` for body text.
- Error red, used sparingly: `#DC2626` for overdue, debt, or risk labels when relevant.

Usage rules:

- Do not make the account all navy or all teal.
- Use amber as an accent, not the dominant color.
- Keep most slides on off-white, navy, or clean UI backgrounds.
- Use red only for real risk moments: overdue, unpaid, missing owner, no next contact.
- Use teal for the CRM "structured solution" moments.

## Typography Style

Use clean, high-legibility sans serif type.

Recommended style:

- Headlines: bold, compact, sentence case or title case.
- Body: medium weight, short lines, no long paragraphs on slides.
- Labels: small uppercase only for UI-style tags, not full sentences.
- Avoid decorative fonts.
- Avoid narrow fonts that become hard to read on mobile.

Text density:

- Reel covers: 3-7 words maximum.
- Carousel slide headlines: 4-10 words.
- Carousel body text: 1-4 short lines.
- UI labels: 1-3 words.

## Reels Cover Style

Each Reel cover should work as a standalone pain statement.

Cover structure:

- Large hook text.
- One simple visual cue: spreadsheet grid, chat bubble, CRM case card, dashboard card, calendar date, document icon.
- Small LegalHub CRM logo or wordmark.
- Optional tag: "Agency Workflow", "Lead Follow-Up", "Case Control", "Documents", "Deadlines", "Owner View".

Cover examples:

- "Too Busy For Chaos"
- "Excel Is Not A Case File"
- "WhatsApp Is Not CRM"
- "No Next Contact?"
- "Owner Is Not The System"
- "Status Is Not Enough"
- "Where Is The Document?"
- "Memory Is Not A Deadline System"

Design rules:

- Keep text away from Instagram UI overlays.
- Use strong contrast.
- Use one screenshot crop or one visual metaphor, not both in a cluttered way.
- Make the cover readable at profile grid size.

## Carousel Style

Carousels should feel like operational checklists, not inspirational slide decks.

Recommended structure:

- Slide 1: sharp pain hook.
- Slides 2-6: one problem or concept per slide.
- Slide 7: LegalHub CRM workflow summary.
- Slide 8: CTA.

Layout rules:

- Use consistent top-left slide numbers.
- Use small tags for persona or topic: "For Owners", "For Case Managers", "Lead Workflow", "Case Control".
- Use thin dividers and simple icons.
- Use screenshots only when they are readable or intentionally cropped.
- Keep each slide visually grounded in a workflow: arrows, cards, lists, or UI callouts.

Do not:

- fill slides with full paragraphs;
- use generic motivational quotes;
- use decorative gradients as the main design;
- put screenshots as tiny unreadable backgrounds;
- overuse stock photos.

## How To Show The CRM Interface

Show the CRM as a response to a specific operational problem.

Best UI moments to show:

- Dashboard: owner visibility, debt/income, active cases, upcoming events.
- Leads: source, status, responsible person, next contact, conversion.
- Clients: structured client profile and related cases.
- Cases: status, service, responsible person, dates, documents, comments, payments, tasks.
- Tasks: priorities, due dates, reminders.
- Calendar: upcoming work.
- Settings: services, statuses, lead sources, users/employees, custom fields.
- Import/export: spreadsheet migration mindset.

UI capture rules:

- Use demo data only.
- Blur or replace any real personal data.
- Zoom into one area at a time.
- Add cursor highlights and short callout labels.
- Avoid long full-screen recordings where the viewer cannot tell what to notice.
- Crop the UI for vertical video, but keep the product recognizable.

Safe UI claims:

- "Lead record."
- "Case record."
- "Task board."
- "Dashboard indicators."
- "Document upload."
- "DOCX templates."
- "Import/export."
- "Configurable statuses and services."

Careful UI claims:

- Integration screens: show only if production readiness is approved.
- Security/privacy wording: use only approved language.
- Pricing/billing: avoid in this launch batch unless final.
- Templates: do not claim legally verified templates.

## Mockups To Use

Recommended mockup types:

- Desktop browser mockups for dashboard, cases, clients, settings, import/export.
- Phone mockups only for WhatsApp/chat pain and Instagram-native story framing.
- Split-screen mockups for "before/after" comparisons.
- Workflow cards for lead -> client -> case sequences.
- Document card mockups for file and template examples.
- Calendar card mockups for deadline content.

Mockup hierarchy:

1. Real approved CRM screenshot with demo data.
2. Cropped UI screenshot with labels.
3. Simplified UI mockup based on confirmed modules.
4. Abstract workflow diagram.

Avoid:

- fake features not in the product map;
- AI chat interfaces;
- client portal screens;
- e-signature, OCR, government API, or automatic billing visuals;
- official provider logos for integrations unless approved.

## How To Make It B2B But Not Boring

Use contrast between chaos and control:

- Start with the messy operational moment.
- Show the missing piece.
- Reveal the CRM workflow.
- End with a practical next step.

Use real agency language:

- "Who owns this case?"
- "Where is the latest document?"
- "What is due this week?"
- "Did anyone call this lead?"
- "What is unpaid?"
- "Which cases are stuck?"

Use motion:

- Chat bubbles collapsing into a case record.
- Spreadsheet row transforming into a case card.
- Lead card moving into client and case records.
- Documents moving from random folders into one case file.
- Sticky notes turning into tasks/calendar events.
- Dashboard cards appearing as owner questions are answered.

Use personality carefully:

- Slightly sharp hooks are good.
- Keep the body practical and respectful.
- Do not shame agencies for using Excel or WhatsApp.
- Frame LegalHub CRM as the next structure, not as a magic fix.

## Visual Content Patterns

### Pattern 1: Pain To Workflow

Use for Reels and product demos.

1. Pain: "The document is somewhere."
2. Risk: "The team cannot see latest context."
3. CRM: case documents and comments.
4. CTA: "Book a document workflow demo."

### Pattern 2: Checklist

Use for carousels.

1. Hook.
2. 5-7 operational items.
3. CRM summary.
4. CTA.

### Pattern 3: Owner Questions

Use for founder posts and dashboard content.

1. "What does the owner need to know this week?"
2. Active cases, upcoming work, debt, recent cases, responsibility.
3. Show dashboard or case list.
4. CTA: owner visibility demo.

### Pattern 4: Before / After

Use sparingly and honestly.

Before:

- spreadsheet;
- chat;
- folder;
- memory.

After:

- lead;
- client;
- case;
- task;
- dashboard.

Do not imply zero setup or instant transformation.

## Screenshot And Demo Data Requirements

Before public publishing, prepare:

- one demo organization;
- fake agency name;
- fake clients;
- fake leads;
- fake cases;
- fake payments;
- fake documents;
- fake comments;
- fake dates;
- fake employees;
- fake services and statuses.

Demo data should include:

- at least 3 leads with different statuses and sources;
- at least 3 clients with related cases;
- at least 5 cases across different statuses;
- one case with uploaded documents;
- one case with payments and debt;
- one task board with due and upcoming tasks;
- dashboard with visible but fictional metrics.

Never show:

- real names;
- real passport numbers;
- real phone numbers;
- real emails;
- real document scans;
- real payment data;
- real integration tokens or settings keys.
