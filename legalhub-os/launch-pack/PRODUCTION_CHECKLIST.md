# Production Checklist - Instagram Launch Pack

Status: practical pre-publication checklist for launch week.

Use this before publishing any Reel, carousel, Story, pinned post, LinkedIn post, or YouTube Community post.

## Production Guardrails

Use only:

- approved demo data;
- confirmed product modules;
- safe language from Marketing OS;
- practical workflow examples from `content-batches/batch-001`.

Do not show or claim:

- real client data;
- real passport numbers, PESEL, phone numbers, emails, addresses, document scans, payment details;
- integration tokens, webhook keys, access keys, OAuth screens, provider secrets;
- automatic WhatsApp import;
- official native Google Sheets integration;
- automated billing or payment collection;
- legally verified templates;
- GDPR/compliance guarantees;
- "never lose a lead" or "never miss a deadline";
- pricing, VAT, trial, or plan promises unless approved.

## CRM Screenshots To Prepare

Required first-week screenshots:

- Dashboard with fake metrics.
- Cases list with fake clients/cases and responsible person.
- Case detail with service, status, responsible person, dates, comments, documents, payments, tasks.
- Documents section with fake file names.
- Payments section with fake case value, paid amount, and unpaid balance.
- Lead list or board with fake leads.
- Lead detail with source, status, owner, next contact, service interest.
- Lead conversion workflow or simplified lead -> client -> case sequence.
- Tasks board with fake tasks.
- Calendar or upcoming events view.

Optional screenshots:

- Client profile with fake data.
- Settings for statuses/services if used in product education.
- Import/export only if discussing spreadsheet migration carefully.

Do not screenshot:

- real organizations;
- real names or client data;
- integration tokens, keys, logs, provider account screens;
- billing/pricing screens unless pricing is approved;
- document templates if legal review status is unclear, unless framed only as `DOCX generation from templates`.

- 1 case with payments and unpaid balance;
- 5 tasks with due/reminder dates;

- dashboard metrics that look realistic but are clearly demo data.

## Data To Hide Or Replace

Always hide:

- full names of real clients;
- real phone numbers;
- real email addresses;
- PESEL;
- passport numbers;
- dates of birth;
- home addresses;
- employer data;
- family data;
- travel history;
- legal stay details tied to real people;
- document scans;
- payment amounts from real customers;
- internal comments about real cases;
- integration tokens, webhook access keys, OAuth IDs, page IDs, logs;
- employee emails if not fake.

Replace with:

- demo names;
- fake emails like `demo@legalhub.example`;
- fake phone numbers;
- fake document names;
- fake payment amounts;
- fake dates;
- fake comments.

Create covers in the style from `VISUAL_DIRECTION.md`.

3. `No Next Contact?`
4. `Every Active Case`

6. `Mini Lead Audit`
7. `Status Is Not Enough`

Pinned post covers:

1. `What LegalHub CRM Is`
2. `Excel + WhatsApp Are Not OS`
3. `See Lead-To-Case Workflow`

Cover rules:

- 3-7 words maximum.
- Strong contrast.
- No tiny UI screenshots as background.
- Keep text away from Instagram UI overlays.
- Add small LegalHub CRM wordmark or mark.
- Use one visual cue: spreadsheet grid, chat bubble, CRM card, dashboard card, calendar date, document icon.

## Texts To Check

Before publishing, check:

- Hook starts with a concrete broken agency moment.
- Caption names one main pain only.
- CTA points to demo, audit, or approved DM keyword.
- No unsupported pricing, security, integration, legal template, or migration claims.
- Uses safe verbs: `helps`, `supports`, `tracks`, `can show`, `built around`.
- Avoids absolute phrases: `guaranteed`, `fully automated`, `never miss`, `never lose`, `no setup required`, `compliant`.
- If early access is mentioned, it says `if available` or has approval.
- If audit is mentioned, the team can actually deliver it.
- If migration is mentioned, it says import/export or workflow migration, not automatic WhatsApp import.

## Before Publishing Each Post

Checklist:

- Asset matches the approved batch-001 script or carousel.
- Screenshots use demo data only.
- Personal data is hidden or fake.
- No integration secrets are visible.
- Cover is readable at profile grid size.
- Caption has one clear CTA.
- Link in bio matches the CTA.
- DM saved reply is ready.
- Comment reply owner is assigned.
- Story poll/question is prepared.
- UTM/tracking link is ready if available.
- Post is reviewed on mobile before publishing.

## After Publishing Each Post

Within first 2 hours:

- Reply to all qualified comments.
- Reply to all story replies.
- Log qualified DMs.
- Send demo/audit link where appropriate.
- Save common objections for future FAQ content.

End of day:

- Record views, saves, shares, profile visits, link clicks, DMs, demo requests, audit requests, qualified leads.
- Note which pain produced the best conversations.
- Decide if the next day's CTA needs minor wording adjustment.

## Final Pre-Launch Checklist

- Profile setup completed.
- Link-in-bio live.
- Demo/audit forms tested.
- First three pinned post briefs approved.
- Week 1 assets produced or scheduled.
- Stories prepared for Days 1-7.
- Saved DM replies loaded.
- Lead log ready.
- Demo organization checked.
- All screenshots reviewed for sensitive data.
- Final approver has checked claims.
- Team knows who replies to Instagram every day.

If any of these are missing, publish only the safest diagnostic content and use DM as the fallback route:

```text
DM "demo" and we will send the next step.
```
